## 1. 设计目标与原则

### 1.1 设计目标

- 支撑商品发布、管理、编辑和状态流转的完整业务闭环。
- 以配置化、版本化方式承载不同商品类型的专属字段。
- 为其他系统提供低延迟、高可用、可观测的商品详情读接口。
- 提供自动化测试及可重复压测证据，而非仅停留在架构描述。

### 1.2 设计原则

- 模块化单体优先：在 Demo 阶段保持部署和调试简单，同时维持清晰模块边界。
- 数据库为事实源：PostgreSQL 保存权威数据，Redis 只作为可重建读缓存。
- 写链路重一致性：事务、不可变模板、乐观锁、提交后缓存失效。
- 读链路重稳定性：缓存优先、穿透保护、热点合并、限流和可控降级。
- 容量驱动演进：分片、集群等复杂能力由实测瓶颈触发，不提前堆砌。

## 4. 数据模型

### 4.1 商品主表`products`

<table><tr><td>字段</td><td>设计</td></tr><tr><td><code>id</code></td><td>UUIDv7，应用生成，支持多实例写入并改善索引局部性</td></tr><tr><td>公共字段</td><td>标题、短标题、富文本详情、金额、库存、类型、状态、发货及退货规则</td></tr><tr><td><code>attributes</code></td><td>JSONB，保存类型专属字段值</td></tr><tr><td><code>schema_version</code></td><td>商品绑定的字段模板版本</td></tr><tr><td><code>version</code></td><td>乐观锁版本号</td></tr><tr><td>时间字段</td><td><code>created_at</code>、<code>updated_at</code></td></tr></table>

金额使用`NUMERIC(18, 2)`，API 以十进制定点值接收并以字符串返回，避免 JavaScript 二进制浮点精度问题。

### 4.2 字段模板表`product\_field\_schemas`

- `(product\_type, version)`唯一标识一个不可变模板。
- `schema JSONB`描述字段键、标签、控件类型、数据类型、必填性、范围和枚举选项。
- 同一商品类型同一时刻只有一个活动模板。
- 模板发布后不可原地修改；变更通过新版本完成。

### 4.3 图片表`product\_images`

- 保存商品 ID、主副图类型、URL、顺序、大小和 MIME 类型。
- 每个商品恰好一张主图，副图最多五张。
- 数据库仅保存元数据和 URL；Demo 使用本地静态存储，生产环境可演进为对象存储与 CDN。

### 4.4 索引策略

- 主键索引支持商品 ID 精确查询。
- `(status, product\_type, updated\_at DESC, id DESC)`支持管理列表组合筛选与稳定排序。
- 标题关键词使用 PostgreSQL 全文检索 GIN 索引，避免前置通配符全表扫描。
- JSONB 不建立无差别的全属性 GIN 索引；只有被证实为高频筛选条件的属性才建立表达式索引。

## 5. 字段可扩展式设计

### 5.1 为什么采用“稳定列 + JSONB + 版本化 Schema”

纯宽表会随业务类型增加产生大量空列和频繁迁移；纯 EAV 模型查询、约束和开发体验复杂；完全无约束的 JSON 又容易积累脏数据。因此采用混合模型：稳定且高频查询的公共字段使用强类型列，变化快的专属字段存入 JSONB，并由不可变模板负责约束。

### 5.2 模板生命周期

（流程图见原文 Mermaid 源码，Docs 在线文档不支持 Mermaid 渲染）

关键约束：

1. 前端选择商品类型后获取活动模板，并按模板生成控件。
2. 发布请求携带商品类型和模板版本。
3. 后端重新读取对应模板，校验公共字段和动态属性，并拒绝未知字段。
4. 若请求中的模板已不再活动，返回`409`，前端刷新模板并要求用户重新确认。
5. 编辑已有商品时不可切换类型，且继续使用商品绑定的模板版本。

### 5.3 扩展成本

新增一种商品类型通常只需要新增模板及对应控件映射，不需要为每个专属字段修改商品主表。需要跨商品查询的新字段则经过访问频率和选择性评估，再提升为公共列或添加表达式索引，避免灵活性侵蚀查询性能。

## 6. 管理写链路与一致性

### 6.1 发布链路

1. 前端获取活动模板并动态渲染表单。
2. 前端执行即时校验，提交类型、模板版本、公共字段和动态属性。
3. 后端重新校验全部规则。
4. 商品和图片元数据在同一 PostgreSQL 事务中写入。
5. 事务成功后返回创建结果，公开详情缓存按首次请求惰性生成。

### 6.2 编辑与状态更新

编辑请求携带`version`，更新 SQL 同时匹配商品 ID 与预期版本，并原子递增版本。匹配不到时返回`409`，阻止并发写入静默覆盖。

批量状态更新先在事务中锁定所有目标商品，再验证全部状态转换；任一商品不存在、版本冲突或状态非法时整批回滚。

### 6.3 缓存一致性

数据库事务提交成功后删除 Redis 详情快照。缓存删除失败不回滚已提交事务，而是记录指标并有限重试。方案接受一个由短 TTL 约束的短暂旧读窗口；本期不引入消息队列或 CDC。

### 7.2 稳定性机制

<table><tr><td>风险</td><td>设计与实现</td></tr><tr><td>缓存穿透</td><td>UUID 格式校验 + 短 TTL 空值缓存</td></tr><tr><td>热点 Key 击穿</td><td>进程内 single-flight + Redis<code>SET NX PX</code>跨实例短锁</td></tr><tr><td>缓存雪崩</td><td>基础 TTL 加随机抖动，避免集中失效</td></tr><tr><td>锁误释放</td><td>随机令牌 + Lua 比较令牌后释放</td></tr><tr><td>Redis 故障</td><td>受并发信号量保护的有限数据库回源</td></tr><tr><td>PostgreSQL 故障</td><td>短超时、不无限重试、快速返回<code>503</code></td></tr><tr><td>流量过载</td><td>Redis 滑动窗口按客户端 IP 限流，返回<code>429</code></td></tr></table>

非重建者只进行有预算的等待，不无限轮询；超出预算后选择受限回源或快速失败，避免请求堆积耗尽连接和协程。

### 7.3 为什么本期不使用布隆过滤器

商品 ID 为 UUID，可先过滤明显非法请求；对格式合法但不存在的 ID，空值缓存已能展示穿透保护。布隆过滤器还需处理初始化、增量同步和误判，因此本期选择更简单、可验证的空值缓存方案。

## 8. 海量商品场景设计

### 8.1 存储与查询

- UUIDv7 改善随机 UUID 对 B-Tree 索引局部性的影响。
- 管理列表当前采用偏移分页并返回总数，满足 Demo 的浅页需求。
- 当数据量导致深分页退化时，演进为基于`(updated\_at, id)`的 Keyset 分页。
- JSONB 属性坚持按真实查询模式建索引，控制写放大与存储成本。
- 图片二进制与关系数据解耦，生产阶段使用对象存储和 CDN。

错误响应统一包含`code`、`message`、`field\_errors`和`request\_id`。主要状态码包括`400`、`401`、`404`、`409`、`413`、`415`、`429`和`503`。

## 10. 安全设计

- 管理员密码以强哈希配置；JWT 密钥由环境变量注入并设置短有效期。
- 富文本经服务端白名单清理，阻止脚本和危险 URL。
- 图片同时校验声明 MIME、实际文件签名、扩展名、大小和数量。
- 所有 SQL 参数化；动态字段名只能来自已发布模板。
- CORS 默认只允许管理前端来源。
- 日志不记录密码、JWT 或完整敏感请求体。

## 11. 可观测性

- API：请求量、P50/P95/P99、2xx/4xx/5xx。
- 缓存：正常命中、空值命中、未命中、重建次数和锁竞争。
- 数据库：回源次数、查询延迟、超时和错误。
- 保护机制：限流次数、降级次数、信号量拒绝。
- 链路定位：每个响应携带`request\_id`，结构化日志关联同一请求。
