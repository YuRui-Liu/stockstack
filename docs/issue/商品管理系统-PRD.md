## 1. 项目概述

### 1.1 背景

商品是 B 端供给体系的基础对象，会被运营后台、交易、营销、搜索与推荐等系统共同使用。本项目已建设一个商品管理全栈 Demo，覆盖商品发布、查询、编辑和状态管理，并针对不同业务类型的字段差异及海量商品、高 QPS 读取场景实现可演进设计。

### 1.2 项目目标

1. 完成商品发布和商品管理的基础闭环。
2. 通过版本化字段模板支持实物商品、虚拟商品、广告素材等不同业务模型。
3. 提供面向其他系统的稳定商品详情读取能力，并以可重复压测验证缓存、热点保护、限流与降级方案。
4. 形成从需求、设计、开发到验证的完整项目实践材料。

## 2. 用户与使用场景

### 2.1 目标用户

- 商品运营人员：发布、查询、编辑商品，执行上下架和处罚操作。
- 业务接入系统：高频读取可售商品详情。
- 开发与评审人员：验证动态字段方案、系统稳定性和工程完整度。

### 2.2 核心用户旅程

1. 管理员登录后台。
2. 选择商品类型，系统加载对应字段模板。
3. 填写公共字段及类型专属字段，完成商品发布。
4. 在管理页按关键词、类型、状态组合筛选商品。
5. 查看或编辑商品，执行单个或批量上下架；必要时将商品设为处罚状态。
6. 其他系统通过公开详情 API 高频读取上架商品。

## 3. 产品范围

### 3.1 本期范围

- 固定管理员账号登录与 JWT 鉴权。
- 商品发布：公共字段、图文信息、服务与售后、动态专属字段。
- 商品管理：分页、组合筛选、详情、编辑、单个上下架、批量上下架、处罚。
- 三类商品：实物商品、虚拟商品、广告素材。
- 版本化字段模板和前后端双重校验。
- 面向其他系统的高 QPS 商品详情 API。
- 初始化数据、自动化测试、k6 压测脚本及报告模板。

### 3.2 非本期范围

- 注册、完整 RBAC、单点登录。
- 草稿、删除、导出、操作审计和处罚恢复。
- 订单、支付、类目、供应商、库存扣减及防超卖。
- 数据库分片、Redis Cluster、CDC、搜索引擎、对象存储与 CDN 的实际部署。

以上能力可作为容量演进方向，不作为本期已实现能力汇报。

## 4. 已交付功能

### 4.1 登录

- 管理员使用配置的固定账号和密码登录。
- 登录成功后签发短期 JWT；前端不保存明文密码。
- 所有管理接口要求有效 JWT，公开详情接口无需登录。

### 4.2 商品管理

- 按商品 ID 或标题关键词查询。
- 按商品类型、商品状态筛选。
- 支持稳定分页并展示总数。
- 列表展示主图、商品 ID、标题、类型、价格、库存、状态和更新时间。
- 支持查看详情、编辑、单个上下架、批量上下架和单个处罚。
- 批量操作采用全有或全无语义，失败时返回相关商品及原因。

编辑已有商品时不可切换商品类型，并继续使用创建时绑定的模板版本，避免历史数据因模板升级产生歧义。

### 4.4 状态规则

- 正常状态允许“下架 → 上架”和“上架 → 下架”。
- 上架或下架商品可通过处罚动作变为处罚状态。
- 处罚商品不能通过普通编辑、单个或批量上下架恢复。
- 处罚恢复不在本期范围内。

### 4.5 公开商品详情

- 仅返回上架商品。
- 下架、处罚和不存在的商品统一返回`404`，避免泄漏内部状态。
- 过载或依赖故障时，分别使用`429`限流或`503`快速失败。

## 5. 加分项一：字段可扩展式设计

### 5.1 业务问题

实物、虚拟和广告素材商品共享标题、价格等公共信息，但专属字段差异明显。如果每增加一种商品就修改数据库表、前后端表单和接口模型，交付成本高且容易产生大量空列和分支逻辑。

### 5.2 产品方案

- 公共稳定字段进入商品主模型。
- 类型专属字段由字段模板定义，商品仅保存对应属性值和模板版本。
- 前端依据模板动态生成控件，后端依据同一模板重新校验。
- 模板发布后不可原地修改；新增或变更字段时创建新版本。
- 历史商品固定绑定原版本，新商品使用当前活动版本。
- 后端拒绝模板外未知字段，防止脏数据进入系统。

### 5.4 业务价值

- 新增商品类型或字段时，主要通过配置模板完成，减少表结构和页面硬编码变更。
- 版本绑定保证历史商品可重复展示、校验和追溯。
- 公共字段仍保持强类型和高查询效率，在灵活性与可治理性之间取得平衡。

## 6. 加分项二：海量商品与高 QPS 场景

### 6.1 场景目标

其他系统可能集中读取热点商品，也可能请求大量不存在的商品 ID。系统需要避免缓存失效导致数据库瞬时过载，并在 Redis 或 PostgreSQL 故障时保持可控行为。

### 6.2 产品能力

- Redis 商品详情快照降低数据库读取压力。
- 空值缓存防止不存在商品持续穿透数据库。
- 同进程请求合并和跨实例重建锁控制热点缓存失效时的回源量。
- 随机抖动 TTL 降低大量缓存同时过期风险。
- 按客户端限流，保护公共接口和下游资源。
- Redis 故障时限制数据库回源并发；数据库也不可用时快速返回`503`。
- 记录缓存命中率、回源量、延迟分位数、限流和依赖错误等指标。

### 6.3 海量数据演进

- 商品 ID 计划使用 UUIDv7，兼顾多实例生成和索引局部性。
- 管理列表使用组合索引，标题关键词使用全文检索索引。
- JSONB 属性仅为被证实的高频筛选字段建立表达式索引，避免无差别索引膨胀。
- 数据量造成深分页退化后，从偏移分页演进为基于更新时间和商品 ID 的游标分页。
- 只有实测证明单机瓶颈后，才依次考虑水平扩容、Redis Cluster、数据库只读副本、按商品 ID 分片、对象存储与 CDN。

## 7. 非功能需求

### 7.1 性能与稳定性验收目标

以下均为待压测验证的目标，不代表当前实测结果：

- 缓存命中场景吞吐相对数据库直读提升至少 5 倍。
- 正常缓存命中场景错误率低于 0.1%。
- 同一热点键失效时，观察窗口内数据库并发回源接近 1 次。
- 压测报告需记录环境、资源、数据量、并发、持续时间、吞吐、P95/P99、错误率、缓存命中率和数据库回源次数。

### 7.2 安全

- 管理员密码使用强哈希，真实密码和 JWT 密钥不进入仓库。
- 富文本执行服务端白名单清理。
- 图片校验 MIME、文件签名、大小、数量和安全文件名。
- SQL 全部参数化，动态字段名只能来自已发布模板。

### 7.3 一致性

- 商品编辑采用乐观锁，防止并发覆盖。
- 商品与图片元数据在一个数据库事务中写入。
- 数据库提交后删除缓存；删除失败记录指标并有限重试。
