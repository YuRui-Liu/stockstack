ARCHITECTURE

架构设计：模块化单体，预留演进空间

采用模块化单体而非过早微服务，模块间通过 Protocol 接口协作，未来可平滑拆分。

系统拓扑
浏览器 :8080 ── Vite/nginx ── FastAPI :8000 ── PostgreSQL └──── Redis（缓存、锁、限流）
读写分离
管理写链路 vs 公开读链路
管理写链路以数据库事务一致性为先；公开读链路以缓存命中率与降级保护为先。两条链路在代码层完全解耦。
金额安全
全链路拒绝浮点数
API 字符串 → DB NUMERIC(18,2) → 序列化字符串，彻底避免 JavaScript 精度歧义。
核心设计决策
1模块化单体
避免 Demo 阶段的分布式复杂度 模块通过 Protocol 接口协作
未来可按领域边界平滑拆分为独立服务
2数据库为事实源
PostgreSQL 保存权威数据 Redis 只作为可重建读缓存
写链路重一致性，读链路重稳定性
3容量驱动演进
分片、集群等复杂能力由实测瓶颈触发 不提前堆砌未验证的分布式组件
清晰模块边界 + 无状态 API + 可重建缓存 = 预留扩容路径

HIGHLIGHT 01

版本化 Schema 驱动的多态商品

L1 业务扩展突破  不同业务场景字段要求截然不同，硬编码会导致模型膨胀。我们引入了不可变、版本化的字段模板机制。

实物商品
Physical Goods
重量、规格、物流模板等专属字段，支持 EMS / 物流 / 卡券三种发货方式。
虚拟商品
Virtual Goods
有效期、核销方式、兑换说明等虚拟属性，适配生服与数字商品场景。
创意素材
Creative Assets
素材类型、投放尺寸、文件地址等广告专属字段，支撑商业化素材管理。
混合模型：稳定列 + JSONB + 版本化 Schema
为什么不用纯宽表
空列膨胀 + 频繁迁移
每增加一种商品就修改表结构，产生大量空列，查询和维护成本持续上升。
为什么不用纯 EAV
查询复杂 + 约束困难
实体-属性-值模型查询、索引和开发体验复杂，难以保证数据一致性。
我们的方案
稳定公共列 + JSONB 动态属性 + 不可变模板约束
稳定且高频查询的公共字段（title、price_amount、stock）使用强类型列；变化快的专属字段存入 JSONB，并由不可变模板负责约束。
模板以 (product_type, version) 唯一标识，发布后不可原地修改。历史商品绑定原版本，新商品使用活动版本，后端拒绝未知字段。
HIGHLIGHT 02

高 QPS 读链路防护体系

L3 高并发突破  构建了一套分层降级、可观测、可压测的公开读防护体系。

1Cache-Aside + 空值缓存
正常商品缓存命中直接返回 不存在商品写入短 TTL 空值，防止穿透 TTL 引入随机抖动，避免集中失效雪崩
2热点回源保护
进程内 Single-Flight 合并并发请求 Redis 分布式锁保证仅 1 个重建者回源 Lua 脚本安全释放锁，避免误删
3限流与降级
滑动窗口 IP 限流 → 429 + Retry-After Redis 故障 → 受信号量约束的 DB 回源 DB 故障 → 503 快速失败，拒绝级联故障
4可观测性
Prometheus 指标：缓存命中/空值/未命中 回源原因、锁竞争、依赖错误、延迟分位值 每个响应关联 request_id，日志不记录敏感信息
七层防护对照表
风险设计与实现
缓存穿透UUID 格式校验 + 短 TTL 空值缓存
热点 Key 击穿进程内 single-flight + Redis SET NX PX 跨实例短锁
缓存雪崩基础 TTL 加随机抖动，避免集中失效
锁误释放随机令牌 + Lua 比较令牌后释放
Redis 故障受并发信号量保护的有限数据库回源
PostgreSQL 故障短超时、不无限重试、快速返回 503
流量过载Redis 滑动窗口按客户端 IP 限流，返回 429
DATA & API

数据模型与 API 设计

UUIDv7 改善索引局部性，金额使用 NUMERIC(18,2) 拒绝浮点数，API 统一前缀 /api/v1。

商品主表 products
混合模型设计
id: UUIDv7，兼顾多实例写入与 B-Tree 局部性
公共字段: title、price_amount(NUMERIC)、stock 等强类型列
attributes: JSONB 保存类型专属字段值
schema_version: 绑定模板版本，历史可复现
version: 乐观锁版本号
索引策略
精准索引，拒绝膨胀
主键索引: 商品 ID 精确查询
组合索引: (status, product_type, updated_at DESC, id DESC) 管理列表
全文检索: PostgreSQL GIN 索引，避免前缀通配符扫描
JSONB: 仅对高频筛选属性建表达式索引，不无差别全属性 GIN
API 契约
方法与路径用途鉴权
POST /auth/login管理员登录否
GET /product-schemas/{type}/active获取活动字段模板是
POST /products发布商品是
GET /products分页与组合筛选是
GET /products/{id}管理端完整详情是
PUT /products/{id}携带版本号编辑是
PATCH /products/{id}/status单个状态更新是
POST /products/batch-status批量上下架是
GET /public/products/{id}高 QPS 公开详情否

PERFORMANCE & EVOLUTION

性能验收与容量演进

提供可复现的压测框架，并为每一步演进预留接口。关键原则：由真实容量数据触发，不提前实现。

四大压测场景
1缓存命中基线
50 VU × 30s P95 < 200ms、错误率 < 0.1% 吞吐目标：相对 DB 直读 ≥ 5×
2数据库直读基线
独立无缓存端点作为对照组 计算真实吞吐倍率 管理 API 需鉴权，不作为基线
3热点失效
100 VU 并发请求同一商品 手动清理缓存键后立即压测 应用指标证明 DB 回源 ≈ 1 次
4Redis 降级
暂停 Redis 服务 验证受限 DB 回源与快速失败比例 Makefile 不自动改 Redis 状态
