# 商品关键词包含搜索设计

## 目标

商品管理列表的关键词搜索同时支持商品标题和商品 ID 的不完整输入。用户输入任意连续片段后，可以找到标题或 UUID 文本中包含该片段的商品。

## 搜索语义

- 接口继续使用 `GET /api/v1/products?query=...`，不改变前端参数、分页或响应结构。
- 查询词先去除首尾空白；结果为空字符串时不添加关键词过滤条件。
- 非空查询词同时匹配两个字段，两个条件之间采用 OR：
  - 商品标题 `title`：不区分大小写的包含匹配。
  - 商品 ID `id`：转换为文本后进行不区分大小写的包含匹配。
- 用户输入的 `%`、`_` 和匹配转义符均按普通字符处理，不允许它们改变包含匹配语义。
- 完整 UUID 不再使用独立的精确匹配分支；包含匹配自然覆盖完整 UUID。
- 商品类型和状态筛选继续与整个关键词条件采用 AND 组合。
- 排序继续使用 `updated_at DESC, id DESC`，分页行为保持不变。

## 数据库实现

在 `ProductRepository.list` 中构造标题和 ID 文本的 `ILIKE` 条件，并使用 SQLAlchemy 的自动转义能力保护通配符。ID 使用 PostgreSQL 文本转换后参与匹配。

现有 `to_tsvector('simple', title)` GIN 索引暂时保留，避免在本次行为修改中混入无关迁移。包含查询在数据量较大时可能无法利用现有索引；若后续性能数据表明需要优化，再单独引入 `pg_trgm` 扩展及相应索引。

## 测试

在真实 PostgreSQL 集成测试中覆盖：

1. 输入中文标题的连续片段能够命中对应商品。
2. 输入商品 UUID 的连续片段能够命中对应商品。
3. 不匹配的商品不会出现在结果中。
4. 现有商品类型、状态、分页和排序行为不变，由现有测试继续提供回归保护。

实现遵循测试驱动流程：先加入测试并确认它因当前全文搜索或 UUID 精确匹配而失败，再修改仓储查询，最后运行相关集成测试及后端测试与静态检查。

## 非目标

- 不支持错别字或编辑距离容错。
- 不搜索短标题、描述、动态属性或图片信息。
- 不新增搜索建议、高亮或相关度排序。
- 不在本次变更中安装 PostgreSQL 扩展或调整数据库索引。
